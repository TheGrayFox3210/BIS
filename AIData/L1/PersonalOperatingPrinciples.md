# ユーザー個別の対話・運用方針

## Scope

- このユーザーとの対話における応答姿勢
- 既存資産の扱い方
- 現在の AI 再構築段階における優先方針

## Layer

- L1: Personalization

## Dependency

- このレイヤーは他レイヤーに依存しない
- このファイル自体は特定の技術や BIS 固有実装を前提に定義しない

## Current Operating Principles

- 既存リポジトリ内のファイルは、過去の開発途中生成物を多く含む前提で扱う
- 既存ファイルの内容を事実として無条件に信用しない
- 現在の会話でユーザーが与えた方針を最優先する
- 以前の運用設計よりも、現在は縮小された実用的な情報管理を優先する
- 現在は「CodexCLI を用いた AI 再構築段階」であると理解して作業する

## Response Style Principles

- 回答は簡潔にまとめる
- 過剰に一般化せず、現在の方針に即して判断する
- 不整合がある場合は、旧ファイルではなく現在のユーザー指示を正とする
- 推測で既存方針を補完しすぎず、必要な前提は明示する

## Default Output Policy

- 出力フォーマットは、その時点のユーザー指示を最優先する
- 固定テンプレートを前提にしすぎない
- 特に形式指定がない場合は、BIS ソリューションの仕様・構造・ルールを自然文で整理した「BIS の Wikipedia 記事風」の記述を既定とする
- 既定出力では、知識ベースの管理都合よりも、BIS 自体の説明として自然に読めることを優先する
- 既定出力では、過度にメタな見出しや運用説明を前面に出しすぎない

## Repository Interpretation Principles

- 既存ドキュメントは「参考資料」または「旧情報候補」として扱う
- 既存コードは「現状の痕跡」として読むが、「現方針の正本」とはみなさない
- 新しい AI 向け定義ファイルは、今後の運用方針を固定する正本候補として整備する

## Codex Client Operation

- Codex は Rider とは独立したクライアントで、`BIS` フォルダ全体をルートとして扱う
- Rider 側のソリューション切替に Codex の文脈を引きずられない運用を基本とする
- Unity / .NET の個別ソリューションはエディタ都合の作業単位であり、Codex は常に BIS 全体文脈を優先して保持する

## Notes

- このファイルはユーザーから現在の会話で与えられた運用方針を要約したもの
- 必要に応じて今後も L1 を更新し、対話方針を明文化する
